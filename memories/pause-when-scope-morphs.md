# Pause When Scope Morphs

When the ask is evolving through back-and-forth, with each message adding or changing scope, Erfan wants me to pause and confirm the target end-state before executing the next increment.

**Why:** an earlier "go" does not license continuing to execute once the task starts changing under new clarifications. The change means the target is not settled, and committing work against a moving target wastes effort and his time.

**How to apply:** when scope shifts across two or more messages, stop, restate the end-state as a crisp decision-shaped fork, get an explicit go, then execute. This is distinct from the "simple/single-step -> just do it" rule, which still holds for settled, well-scoped asks. The most recent message wins over any earlier blanket go-ahead.
