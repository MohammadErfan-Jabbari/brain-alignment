# /write redesign — step 2b · the scenario suite (TDD-for-writing)

The acceptance/regression suite for the functionality matrix (`write-redesign-design.html` v0.5). Each scenario
tests ONE functionality with a concrete input and an expected behavior. **DET** = assertable pass/fail (the hard
regression suite → hooks). **RUB** = rubric-graded by a judge (taste/structure/argument-validity, with a stated
pass criterion). Generated by 6 per-concern subagents, grounded in our real ladder + Claudio + the canon, then
curated. **Format:** `ID | tests: F## | DET|RUB | INPUT | EXPECT | GROUNDED`.

> **The permanent regression anchor:** SC-VOICE-01..04 are Claudio's four flagged sentences verbatim. Any future
> `/write` that fails these four has not solved the ground-truth failure. They never leave the suite.

> **The pattern (a design finding):** good prose concentrated in **Results / Methods / Limitations**
> (mechanism-before-metric, hedged nulls, named confounds, honest limitations); violations concentrated in
> **Abstract / Discussion / Conclusion framing** (agency-to-abstraction, stock phrases, scope overclaim). The
> danger zone is the opening/closing framing paragraphs — F12/F10 should weight them.
