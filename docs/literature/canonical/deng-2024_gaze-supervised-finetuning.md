## Comprehension Summary [REQUIRED]

1. Problem solved: Human gaze (scanpaths) carries cognitive structure that may improve LM text
   representations, but real gaze is costly and unavailable at deployment. Deng et al. ask whether a
   *synthetic* scanpath — generated on the fly by a pretrained scanpath model (Eyettention) — can be
   used as an auxiliary fine-tuning signal that helps a pretrained encoder LM on GLUE, especially
   low-resource, while leaving the deployed model identical to a standard fine-tuned LM (the gaze
   branch is removed at inference, so application-time compute is unchanged).

2. Core insight: Rather than predict gaze features, they use the *order* of fixations. A synthetic
   scanpath (a fixation-index sequence over the sentence's tokens) is generated by Eyettention; the
   contextualized token embeddings are **rearranged into that fixation order**, run through a GRU
   "scanpath encoder," and fed to a parallel dense head. The total loss is
   $\mathcal{L} = \mathcal{L}_{\text{standard}} + \lambda \mathcal{L}_{\text{scanpath}}$, where both
   $\mathcal{L}$ terms are the task loss (cross-entropy for classification, MSE for STS-B). The
   scanpath branch backpropagates "cognitive" gradients into the shared Transformer. At test time
   the scanpath module is dropped.

3. If-wrong breakage: The whole brain/cognition claim rests on Table 4 (Scanpath vs Random Order).
   If shuffling the fixation order ("Shuffle SP") matched the real-order gain, the effect would be
   "a second auxiliary head / token-order diversification regularizer," not anything gaze-specific.
   They run exactly that control and report a drop — but a small one (Avg 80.15 → 79.82 for Shuffle
   SP, → 78.45 for fully Random Shuffle, over 4 tasks), with no significance test. So the
   gaze-order-specific increment exists but is ≈ 0.3 pp average and untested.

4. Main result location: Table 1 (low-resource GLUE, K = 200/500/1000); Table 2 (high-resource, full
   GLUE dev); Table 3 (scanpath-module placement ablation); Table 4 (shuffle controls). Method in §2
   and Fig. 1; data/hyperparameters in Appendix A–B.

## Source Grounding

**Pretrained LMs (base models).** BERT_base (Devlin et al. 2019) and RoBERTa_base (Liu et al. 2019)
— both **encoder-only** 12-layer Transformers, hidden dim 768, from the HuggingFace checkpoints. **No
decoder / autoregressive LM is used.** All experiments are full end-to-end fine-tuning; the "[CLS]"
last-hidden state feeds a newly initialized dense classification/regression head.

**Eye-tracking corpus (enters only via Eyettention).** The LM never sees real gaze. Real gaze enters
only as the *pretraining* corpus of the scanpath generator: Eyettention is pretrained on the **L1
(native-English) subset of CELER** (Berzak et al. 2022) — eye-tracking recordings of native English
speakers reading natural sentences. **Not ZuCo, not GECO, not Provo, not Dundee.** Single domain,
narrow text-difficulty range (a limitation the authors flag).

**Scanpath generator.** Eyettention (Deng et al. 2023b), an attention-based dual-sequence model that
simulates a human reading scanpath (fixation sequence) for a given sentence. It embeds a pretrained
LM in its text encoder; Deng et al. **match that internal LM to the base LM under test** (BERT-in-
Eyettention when evaluating BERT, RoBERTa-in-Eyettention for RoBERTa) so the fixation indices align
with the tokenizer. Eyettention is itself fine-tuned per downstream task alongside the LM.

**Architecture (Fig. 1, training time).**
- Transformer encoder → contextualized token embeddings (each tied to a position index).
- Eyettention generates a synthetic fixation-index sequence for the same sentence (Fig. 1 example:
  fixation index [2, 4, 5, 3]).
- "Scanpath Module" rearranges the token-embedding sequence into that fixation order.
- "Scanpath Encoder": a **unidirectional GRU, hidden size 768, dropout 0.1**, hidden state
  initialized from the LM's final-layer [CLS] output; processes the reordered sequence.
- The GRU's last step → a shared dense layer → second prediction. This branch's loss is
  $\mathcal{L}_{\text{scanpath}}$.
- Standard branch ([CLS] → dense) gives $\mathcal{L}_{\text{standard}}$.

**Training objective.** $\mathcal{L} = \mathcal{L}_{\text{standard}} + \lambda
\mathcal{L}_{\text{scanpath}}$, $\lambda$ searched per task over {1, 0.7, 0.5, 0.3, 0.1, 0.01,
0.001} on the dev set.

**Downstream tasks (GLUE).** 8 tasks: SST-2 (acc), CoLA (Matthews corr), MRPC (F1), STS-B (Spearman),
QQP (F1), MNLI (acc), QNLI (acc), RTE (acc). Test = original GLUE dev sets; an extra 1,000 instances
held out from train as the dev set. Low-resource: K ∈ {200, 500, 1000} sampled training instances.
High-resource: full training set.

**Baselines.** (1) Standard text-only fine-tuning ($\mathcal{L}_{\text{standard}}$ only). (2) EDA
(Easy Data Augmentation; Wei & Zou 2019) — random word insertion/replacement/swap/deletion;
n_aug ∈ {1,2,4,8,16} tuned. **The baselines are parameter-matched at inference (same BERT/RoBERTa)
but not training-compute-matched** — the +SP model trains an extra GRU branch and fine-tunes
Eyettention; EDA trains on an enlarged dataset. No FLOP/step-matched control is reported.

**Seeds / hardware.** Low-resource: 5 runs with different *data* seeds {111,222,333,444,555}; the
*model* training seed is fixed s=42 across all models (so the 5 SEs are data-sampling variance, not
init variance). High-resource Table 2 reports single dev-set numbers (no SE). 10 epochs low-resource,
20 high-resource; AdamW, max seq len 128, batch 32; LR tuned per task (BERT {5e-5,4e-5,3e-5,2e-5},
RoBERTa {3e-5,2e-5,1e-5}). One NVIDIA A100-40GB.

## Key Ideas

### Finding 1 — Low-resource gain over standard fine-tuning and EDA (Table 1)

+SP consistently beats both standard FT and EDA in the K = 200/500/1000 regime. Headline averages:
"performance gains of 2–3% for BERT and 1–2% for RoBERTa over standard fine-tuning," largest at
smallest K. Per-task: +SP beats standard FT on **all 8 tasks for BERT** at every K; for RoBERTa it
wins on 5/8 (K=200), 5/8 (K=500), 4/8 (K=1000). Concrete BERT averages (Table 1, last column):

| K | BERT std | BERT +EDA | BERT +SP | RoBERTa std | RoBERTa +EDA | RoBERTa +SP |
|---|---|---|---|---|---|---|
| 200 | 61.45 | 62.67 | **63.28** | 65.84 | 67.20 | **67.20** |
| 500 | 67.43 | 68.11 | **69.10** | 73.05 | 72.06 | **72.3** |
| 1000 | 70.66 | 70.67 | **72.3** | 75.91 | 75.05 | **76.78** |

EDA *hurts* CoLA and STS-B for BERT (e.g. CoLA K=200: std 18.52 → EDA 14.05), where +SP still helps
(→ 23.33) — the authors argue random text edits destroy the acceptability/similarity signal while
scanpath reordering preserves it.

### Finding 2 — High-resource gain is small (Table 2)

On full GLUE dev, +SP still gives the best overall average (BERT 84.25 vs std 82.75; RoBERTa 86.47 vs
std 85.96) but the per-task picture is mixed and several tasks carry the "†" (worse than standard FT)
dagger. The authors say the gains "are not as significant as in the low-resource setting." So the
method's value is concentrated in the data-scarce regime.

### Finding 3 — Module placement: top layer is best (Table 3)

Putting the scanpath module after the last Transformer layer (AfterLayer-12 / on top of [CLS]
embeddings) gives the best average (80.15 over SST-2/CoLA/MRPC/RTE); placing it after layer 11/8/5 or
on the embedding layer gives smaller gains. They attribute this to upper layers carrying richer
semantics (Jawahar et al. 2019). Adding extra positional embeddings to the reordered sequence has
only marginal effect.

### Finding 4 — Fixation ORDER matters (Table 4) — the load-bearing control

Two destructive controls on the reordering: **Shuffle SP** (shuffle the scanpath ordering) and
**Random Shuffle** (drop the scanpath, randomly shuffle token embeddings). Averages over
SST-2/CoLA/MRPC/RTE:

| Variant | SST-2 | CoLA | MRPC | RTE | Avg |
|---|---|---|---|---|---|
| BERT (standard) | 92.43 | 59.90 | 90.51 | 66.79 | 77.41 |
| +SP (real order) | 93.23 | 64.27 | 91.60 | 71.48 | **80.15** |
| +Shuffle SP | 93.00 | 63.81 | 91.34 | 71.12 | 79.82 |
| +Random Shuffle | 92.78 | 60.66 | 91.42 | 68.95 | 78.45 |

Reading: the *whole* benefit over standard FT is +2.74 pp avg. Of that, Random Shuffle (any reorder +
GRU branch, no gaze) already recovers +1.04 pp; Shuffle SP (a scanpath but with its order destroyed)
recovers +2.41 pp; the **real fixation order adds only +0.33 pp over Shuffle SP and +1.70 pp over
Random Shuffle**. So most of the gain is "extra auxiliary branch + reordering as augmentation," and
the genuinely gaze-order-specific slice is small and untested for significance.

## Evidence

- **Primary:** Table 1 low-resource GLUE, 5 data seeds, means ± SE, dagger marks where a variant is
  worse than standard FT. +SP avg beats standard FT by ~2–3 pp (BERT) / ~1–2 pp (RoBERTa); gains
  shrink as K grows.
- **High-resource:** Table 2, single dev-set run (no SE) — small mixed gains.
- **Ablations:** Table 3 (placement), Table 4 (shuffle controls).
- **No OOD, no adversarial robustness, no cross-domain transfer, no learning-curve/sample-efficiency
  plot.** "Low-resource" here = small random subsamples of the *same* GLUE distribution, evaluated
  on the *same* GLUE dev set — strictly in-distribution. There is no test split from a different
  domain.
- **No statistical test** on the +SP vs standard, +SP vs EDA, or +SP vs Shuffle-SP differences; only
  means ± SE (5 data seeds) for Table 1, and bare numbers for Tables 2–4. The "†" dagger is a raw
  comparison, not a test.

## Limitations

1. **Synthetic, not real, gaze — and a weak generator.** The LM is supervised by Eyettention output,
   and Eyettention is pretrained on a small, single-domain CELER L1 subset. The authors explicitly
   flag this: the generator's limited training data "may restrict the knowledge acquired … leading to
   limited benefits." RoBERTa benefits less than BERT, which they attribute to RoBERTa's stronger
   pretraining swamping a weak scanpath signal.
2. **Gaze-specific increment is tiny and untested.** Per Table 4, real fixation order adds ~0.33 pp
   over a shuffled scanpath; no significance test. Most of the headline gain is the auxiliary-branch /
   reordering-augmentation effect, not gaze content per se.
3. **In-distribution GLUE only.** No OOD, robustness, or true sample-efficiency curve. "Low-resource"
   is subsampled in-domain data, same eval distribution.
4. **No compute-matched baseline.** +SP trains an extra GRU branch and fine-tunes Eyettention; the
   comparison to standard FT is not step/FLOP-matched, so part of the gain could be "more training
   capacity," partially probed (but not isolated) by the Random Shuffle control.
5. **Order, not gaze features.** Fixation *durations*, regressions, skips are not used as targets —
   only the *sequence of fixated token indices*. The cognitive content is reduced to a permutation.
6. **Encoder-only, English-only.** BERT/RoBERTa base; CELER L1 native-English readers.

## Relevance to this thesis

**Which assumption / experiment this touches:** A3 (does an induced cognitive-alignment signal buy
practical downstream benefit?) and directly **E021** (T1.3) — the surprisal-residualized
reading-time/EEG auxiliary-training experiment on a small decoder LM. **This is the closest published
prior art to E021 and the paper we must position against to avoid being scooped.**

**What Deng et al. DID (so we don't re-claim it):**
- Encoder LMs (BERT/RoBERTa base), supervised by a *synthetic scanpath* (fixation-order permutation),
  via an auxiliary GRU branch dropped at inference, on GLUE, with a low-resource (in-distribution
  data-scarce) story and the right shuffle controls.

**How E021 differs / what is still open after Deng — point by point:**

1. **Surprisal-residualization — NOT done by Deng.** Deng uses the *raw* synthetic scanpath order; no
   component is regressed out against the model's own surprisal. Our T1.3 gate's decisive concern is
   exactly that reading-time/N400 are largely predictable from LM surprisal, so a raw cognitive target
   is circular. E021's novel move (strip the surprisal-predictable component, test the residual) is
   entirely uncovered here. **This is the cleanest unscooped axis.**

2. **Decoder LMs — NOT done.** Deng is encoder-only (BERT/RoBERTa). E021 uses a small *decoder* LM.
   Open.

3. **OOD / robustness / true sample-efficiency — NOT done.** Deng's "low-resource" is subsampled
   in-distribution GLUE on the same dev set; no OOD split, no robustness, no learning-curve. E021's
   judged outcome (downstream sample-efficiency / OOD) is uncovered. Open.

4. **Matched-budget / matched-perplexity framing — NOT done.** Deng is parameter-matched at
   inference but not compute/step-matched in training, and runs no perplexity-matched control. E021's
   matched-budget + permuted-twin protocol is the rigor Deng lacks.

5. **EEG arm — NOT done.** Deng uses behavioral gaze (fixation order from CELER) only; no
   electrophysiology. The EEG-*guided-training* arm of E021 (vs EEG decoding) is genuinely unscooped.

6. **Cross-modal / multi-signal protocol — NOT done.** Deng is single-signal (synthetic scanpaths).
   E021 / the expansion program tests one residualization protocol across fMRI + behavioral + EEG as
   a *general* claim. Uncovered.

**The one piece Deng DOES cover that E021 must cite, not duplicate:** the behavioral, raw-gaze,
encoder-LM, in-distribution-GLUE corner. Our idea-tree already records this correctly ("behavioral is
partly scooped (Deng ACL'24: raw gaze, BERT, in-dist GLUE, no residualization/matched-ppl)"). Deng's
Table 4 is also a useful prior: even with the *right* shuffle control, the gaze-order-specific
increment is ~0.3 pp and untested — a low floor that strengthens our null-as-publishable framing
(if raw cognitive signal barely beats its own shuffle, residualizing it away should give ≈ 0, and a
surviving residual would be the genuinely new positive).

**One-line relevance:** Closest prior art to E021 — Deng et al. fine-tune BERT/RoBERTa with a
*synthetic raw-scanpath* auxiliary branch on in-distribution GLUE and get ~2–3 pp low-resource gains
of which only ~0.3 pp survives a shuffle control; they do **not** residualize against surprisal, use
no decoder LM, no EEG, no OOD/sample-efficiency, and no matched-budget control — exactly the six axes
E021 owns.
